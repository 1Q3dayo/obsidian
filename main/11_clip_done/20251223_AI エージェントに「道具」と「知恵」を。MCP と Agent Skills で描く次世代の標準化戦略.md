## はじめに

最近、Agent Skills がオープンスタンダードとして公開されましたね。これ、MCP と同じように、これからのエージェント開発におけるデファクトスタンダードになりそうな感じ（もう既に？）がプンプンです。

そこで今回は、MCP と Agent Skills という注目の 2 大技術について、「何が違うのか？」「どう補完し合うのか？」「私たちはどう使い分ければいいのか？」といったポイントを整理して行きたいと思います。

## MCP(Model Context Protocol)：AI のための「接続性レイヤー」

AI エージェントが本当の意味で役に立つためには、外部のデータやツールとスムーズに連携できる能力が欠かせません。

MCP の戦略的な役割は、AI モデルと外部データの間に「抽象化レイヤー」を設けることにあります。

これは、「モデルの開発」と「ツールの開発」を切り離すことを意味します。長期的なエコシステムの健全性にとって、これは非常に重要な一歩です。これにより、モデルやツールがそれぞれ個別に進化しても、お互いの互換性が保たれ、開発効率と拡張性が一気に高まります。

### MCP を支える 3 つのコンポーネント

MCP のアーキテクチャは、役割がはっきりと分かれた 3 つの要素でできています。

- **MCP Host**: ユーザーと対話する窓口となる AI アプリ（例: Claude Desktop, VS Code）。どこと通信するかを決める司令塔（オーケストレーター）です。
- **MCP Server**: 外部データやツールへの扉を開く独立したプロセス。データベースを操作したり、Google カレンダーを動かしたりする実務担当です。
- **MCP Client**: Host に組み込まれ、Server との実際のやり取り（握手やメッセージの送受信）を管理する通信モジュールです。

通信の土台には、軽量な `JSON-RPC 2.0` プロトコルが使われています。接続方法も、ローカル開発に便利な `Stdio` （標準入出力）と、リモートサービス向けの `SSE over HTTP` （Server-Sent Events）の両方をサポートしており、使い勝手も抜群です。

### 3 つの基本要素

MCP はただ関数を呼ぶだけではありません。以下の 3 つの要素を通じて、AI にリッチな情報（コンテキスト）を届けます。

| **プリミティブ** | **何ができるの？** | **具体例** | **AI での役割** |
| --- | --- | --- | --- |
| **Resources (リソース)** | 読み取り専用のデータを提供 | ログ、最新の為替、DB スキーマ | 「今の状況」や「参照データ」を注入 |
| **Tools (ツール)** | AI が実行できる関数を提供 | SQL 実行、Slack 送信、Git コミット | 「世界への働きかけ」を可能にする |
| **Prompts (プロンプト)** | テンプレートを提供 | コードレビュー指示、バグレポ形式 | タスクの開始や入力をスムーズにする |

### MCP を導入する戦略的メリット

1. **接続性の民主化**: 従来、10 個のアプリを 20 個のツールに繋ぐには 200 通りの開発が必要でした。MCP なら、10 個のクライアントと 20 個のサーバー、計 30 個の実装で済むようになります（N 対 M 問題の解消）。
2. **開発スピードの向上**: UI や認証を毎回作り直す必要がなくなり、ツールの核となるロジック開発に集中できます。
3. **セキュリティが明確**: サーバーは別プロセスで動くので、API キーなどの機密情報を AI アプリ側に渡さず安全に運用できます。
4. **リアルタイムな推論**: 静的なデータを使う RAG と違い、常に最新のデータソースに繋がるため、株価やサーバー負荷に合わせた「今」の判断が可能です。

### 気をつけるべき課題とデメリット

- **コンテキストの圧迫**: サーバーにツールがたくさんあると、その説明文だけで数千トークン消費してしまいます。これが「コンテキスト爆発」を引き起こし、AI の推論を鈍らせることがあります。
- **インフラ管理の手間**: サーバーを常に動かしておくためのホスティングや監視といった運用コストがかかります。
- **ネットワークの遅延**: リモート接続の場合、通信の遅れがエージェントの動作スピードに直結します。

実は、この「コンテキスト爆発」という課題こそが、次にご紹介する **Agent Skills** が求められる大きな理由でもあるんです。

## Agent Skills：エージェントへの「熟練度と手順」の伝承

MCP が「道具」なら、Agent Skills は「その道具の正しい使い方」を教える知識レイヤーです。Anthropic の開発チームは、これを「 **新入社員へのオンボーディングガイド** 」に例えています。

これまでは巨大なプロンプトに手順を詰め込んでいましたが、Skills を使えばこの「手順の知恵」を部品化（モジュール化）して、賢く管理できるようになります。

Agent Skill の正体は、特定のルールで作られたフォルダです。その中心に `SKILL.md` というファイルがあり、中身は大きく 2 つに分かれています。

```shell
pdf-skill/
├── SKILL.md (main instructions)
├── FORMS.md (form-filling guide)
├── REFERENCE.md (detailed API reference)
└── scripts/
    └── fill_form.py (utility script)
```

- **YAML Frontmatter**: ファイル冒頭のメタデータ。「スキルの名前」や「どんな時に使うか」の短い説明を書きます。
	```yaml
	---
	name: pdf-processing
	description: Extract text and tables from PDF files, fill forms, merge documents. Use when working with PDF files or when the user mentions PDFs, forms, or document extraction.
	---
	```
- Markdown Body: 具体的な手順、ガイドライン、制約、例などを Markdown で詳しく書きます。
	必要なら Python スクリプトやテンプレートファイルも一緒に同梱できます。
	```markdown
	\`\`\`python
	import pdfplumber
	with pdfplumber.open("document.pdf") as pdf:
	    text = pdf.pages[0].extract_text()
	\`\`\`
	```

### 革新的なメカニズム「プログレッシブ・ディスクロージャー」

Agent Skills の凄いところは、「 **Progressive Disclosure（段階的開示）** 」という仕組みです。コンテキストを節約するための 3 ステップで動きます。

1. **Discovery (発見)**: 起動時は、全スキルの「名前と短い説明」だけを読み込みます（1 スキル数十トークン程度）。
2. **Activation (有効化)**: ユーザーの依頼を見て「このスキルが必要だ」と判断した瞬間だけ、 `SKILL.md` の全文を読み込みます。
3. **Execution (実行)**: さらに深くスクリプトやドキュメントが必要になった時にだけ、それらをオンデマンドでロードします。

このおかげで、1,000 個のスキルを持っていても、AI の頭（コンテキスト）がパンクすることはありません。

### コード実行で「確実な結果」を出す

Skills はコード実行と組み合わせると最強です。

AI の「たぶんこうかな？」という曖昧な推論に頼るのではなく、スキル内の Python スクリプトを走らせることで、計算間違いのない決定論的な処理ができます。例えば「PDF から請求額を計算する」なら、専用ライブラリに任せたほうが 100%正確ですよね。これらは安全なサンドボックス環境で実行されるので安心です。

### Agent Skills のメリットと限界

**メリット:**

1. **圧倒的なトークン効率**: 段階的な開示で、AI の記憶容量を節約できます。
2. **高いポータビリティ**: フォルダをコピーするだけなので、共有や管理がすごく楽です。
3. **信頼の再現性**: スクリプト化されているため、誰がやっても同じ結果が得られます。

**限界:**

- **動的な変化に弱い**: 基本は静的なファイルなので、API の仕様変更などには手動での更新が必要です。
- **実行環境が必要**: スクリプトを動かすために、エージェント側に Python などの環境が整っている必要があります。

## MCP と Agent Skills：対立ではなく「最強のパートナー」

「どっちがいいの？」という議論をたまに見かけますが、それは少し違います。この 2 つは役割が違うだけで、組み合わせて使うことで初めて 100%の力を発揮します。

### 比較まとめ

| **比較ポイント** | **MCP (接続性)** | **Agent Skills (知恵・手順)** |
| --- | --- | --- |
| **主な役割** | **「つなぐ」** | **「こなす」** |
| **例えると？** | USB ポート、API、ドライバ | レシピ、マニュアル、SOP |
| **提供物** | データアクセス、ツール実行権 | 実行手順、判断基準、ノウハウ |
| **コンテキスト消費** | **高い** （常時ロード） | **非常に低い** （オンデマンド） |
| **データの鮮度** | リアルタイム（DB/API 直結） | 静的（または実行時のみ） |
| **導入コスト** | 高（サーバー構築が必要） | 低（テキストを書くだけ） |

### 具体的な活用シナリオ：「売上レポートの作成」

- **MCP の役割**: 社内 DB に **安全に繋ぎ** 、SQL を叩くための「 **手段** 」を提供します。
- **Skills の役割**: 「どの SQL を書くか」「異常値の基準は？」「レポートの形式は？」といった組織の「 **知恵** 」を提供します。

MCP だけだと「道具を持った素人」、Skills だけだと「知識はあるけど手足がない評論家」。両方揃って初めて、エージェントは自律的な「 **熟練のパートナー** 」になれるのです。

## 戦略的ガイド：どう導入していくべきか

### 個人開発者・パワーユーザー

**「Agent Skills」から始めて、自分だけの秘伝のタレを作ろう**

- 毎月の請求書処理などは Python スクリプト付きの Skill にまとめましょう。
- 自分のコーディングルールを `SKILL.md` に書けば、AI が自分好みのコードを書く専用アシスタントに進化します。
- MCP は、どうしても必要なローカル DB 操作などに絞って使うのがスマートです。

### 企業・組織

**「MCP をインフラ、Skills を業務標準」として配布するハイブリッド戦略**

- **セキュアなアクセス**: 基幹システムへの接続は IT 部門が管理する MCP サーバーに集約し、ガバナンスを効かせます。
- **業務プロセスの標準化**: 「障害対応」や「コンプライアンスチェック」の手順を Skill 化し、全社に配ります。これにより、業務の属人化を防げます。
- この戦略のキモは、「 **AI モデルに依存しない、自社だけのナレッジ資産** 」を持てることにあります。

## まとめ

MCP は AI を「箱の中」から解放し、Skills は AI に「プロの知恵」を授けました。この両輪が揃うことで、AI は単なるチャット相手から、真のパートナーへと進化します。

- **個人の方**: まずは 1 つ、自分の定常業務を **Agent Skill** に書き出してみてください。
- **組織の方**: IT 部門は **MCP** のロードマップを、現場は **SOP（標準手順）の Skill 化** を、今すぐスタートさせてください。

AI エージェントが切り拓く未来は、もうすぐそこまで来ています。この新しい標準を武器にして、変革の波を楽しんでいきましょう！
