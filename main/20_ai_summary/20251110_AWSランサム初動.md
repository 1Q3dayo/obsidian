## 要約
Serverworks が実施したランサムウェア対策セミナーの振り返り記事。多層防御やマルチアカウント戦略を前提に、NISTサイバーセキュリティフレームワーク（Identify/Protect/Detect/Respond/Recover）に沿ってAWSネイティブサービスをどの順番で組み合わせるかを示している。

## 重点ポイント
- **Identify**: AWS Config、Systems Manager Inventory、Amazon Macie、Resource Explorer、タグ分類で資産と機密データを棚卸しする。
- **Protect**: 静的IAMキー排除とIAM Identity Centerでの一時クレデンシャル化、Roles AnywhereやMFA強制、Inspector+Patch Managerによる脆弱性対応、Network Firewall・Security Groups・S3 Block Public Access・Macie・CloudTrail保護などで侵入と横移動を抑止。
- **Detect**: Amazon GuardDutyを基軸にSecurity Hub、Cost Anomaly Detection、CloudWatchアラームなどで兆候を監視する。
- **Respond/Recover**: IAM Incident Manager、SSM Automation、Backup Vault LockやS3 Object Lock、クロスアカウントのBusiness Continuity OUで論理的エアギャップを確保し、ランサム起点の破壊から復旧する流れを定義。

## メモ
- 静的アクセスキーや未設定タグといった基本の抜け漏れがランサム侵入口になりやすいと強調。検知・復旧を強くしてもProtectが甘いと効果が出ないという警告付き。
