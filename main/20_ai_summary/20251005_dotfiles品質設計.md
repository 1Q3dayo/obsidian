## 要約
dotfilesリポジトリを単なる設定集ではなく「テスト可能な環境構築ツール」にするためのアーキテクチャを、筆者の`shunk031/dotfiles`を例に解説。chezmoiのテンプレートでOS別設定を切り替えつつ、`home/`（設定）、`install/`（セットアップスクリプト）、`tests/`（Batsテスト）の3レイヤーで構成している。

## 重点トピック
- chezmoiはGoテンプレートで`.gitconfig.tmpl`などに変数を埋め込み、`sh -c "$(curl ... get.chezmoi.io) -- init --apply"`のワンライナーで新マシンを初期化できる。
- Batsで各インストールスクリプトを単体テストし、`kcov`でカバレッジ取得→Codecovにアップロード。GitHub ActionsではmacOS/Ubuntu行列でテストし、`setup.sh`を毎週cron実行してエンドツーエンド検証＆ベンチマーク（shell起動時間）も自動化。
- スクリプトは`set -Eeuo pipefail`や`if [["${BASH_SOURCE[0]}" == "${0}" ]]`など安全なテンプレに従い、OS/責務ごとにファイルを分割。TDDで新ツールを追加し、`install/` と `tests/` 両方を更新する流れが顧客体験を安定させる。

## メモ
- GitHub Pagesでベンチマーク履歴を公開し、プラグイン追加などがログイン時間に与える影響を可視化。パフォーマンス劣化の早期検知にも役立つ。
- chezmoiのデフォルトソースディレクトリやテンプレ構文に触れ、複数OSで同じファイルを扱う際のコツも散りばめられている。
