## 要約
GitHub Blogで紹介された「Spec-driven development」を、技術メディアが詳細にレビューした記事。GitHub Brain MCP Serverの開発を、Goコードを書かずMarkdownのみで行い、Copilotに`main.md`→`main.go`の変換を繰り返させる流れを追体験する。仕様と文脈をMarkdownに集約することで、エージェントのコンテキスト切れやインストラクション更新漏れを防ぐことが狙い。

## 重点トピック
- ディレクトリ構成は`.github/prompts/compile.prompt.md`（仕様からソースを生成するプロンプト）、`main.md`（宣言的仕様）、`main.go`（生成物）、`README.md`（ユーザー向け）とシンプル。
- `main.md`にはCLIワークフロー、GraphQL問い合わせ、SQLite利用方針などを自然言語＋コードブロックで記述し、「仕様を明確に書く方がGoを書くより難しい場面もある」と実感が語られる。
- `compile.prompt.md`をタスクランナーのように使い、「仕様に従ってGoを更新」「VS Codeタスクでビルド」「依存ライブラリごとに理由を書く」などの指示を毎回再利用。カスタムインストラクションを逐次直すよりも、仕様書で一元管理できるメリットが強調される。

## メモ
- 仕様書にはREADMEのインポートも含め、Copilotに対してユーザードキュメントと実装要求を同じコンテキストで見せている。
- Markdownを「プログラミング言語」と呼ぶのは、Heading/リスト/コードブロックを利用して振る舞いを機械可読に近づける工夫が前提であり、Spec Kitのようなツールチェーンを併用することで実効性が出てくるという文脈。
